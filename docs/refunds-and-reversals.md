# 实际退款与退款冲销（0.1.9+10 / SQLite v11）

本次仅完成用户指定的实际退款、退款冲销及其必要账务接入；资料启停不在本次范围。
实现和自动化验证完成，不代表完整ERP或新版本真机验收通过。后续已按用户“更新”要求同签名覆盖手机，保留数据；没有卸载或清空。

## 使用

销售单详情 → **实际退款与冲销**。

1. 在待退款来源卡片中核对客户、归属段和剩余金额，选择“登记已实际退款”。
2. 填写实际退回金额、实际渠道和可选备注，确认钱已实际退给该客户，再登记。
3. 可以分次登记；另一部分仍可从销售详情转入客户余额，两种处理共用剩余上限。
4. 登记有误时，在原退款下选择“冲销误登记退款”，填写原因，并确认误登记或退款资金已收回。
   冲销整条所选退款记录；如只需纠正其中一部分，先冲销原条，再按实际事实分次重登。
5. 请求结果不明时，使用“原请求重试”或重新查询。重进页面会读取持久化请求，不自动重复入账。
   “取消未入账请求”只取消软件中尚未入账的请求，不会撤回转账。已入账请求不能取消。

软件不执行转账。实物退货仍须另行确认；登记退款不改变库存。
冲销保留原退款和关联反向事件，不删除原记录，不改写历史金额。

## 账务与数据规则

- 待处理 = 对应客户归属段实际收款 − 净实际退款 − 已转余额 − 当前归属段合同金额。
  旧客户归属段不再扣当前客户合同金额；只显示正的待处理金额。
- 当前有效收款 = 实际收款 − 已转余额 − 净实际退款；应收再扣已分配的客户余额。
- 所有写入在SQLite事务内重新核对版本、客户、来源、数量和可处理金额。
  同键同内容重试返回原事件；同键不同内容拒绝。退款与转余额并发不能超额。
- 退款按登记时间和渠道计入当日日结流出；冲销按冲销登记时间和原渠道计入反向资金事件。
  当日已日结，不能追加退款或冲销；原退款日期已日结，即使次日也禁止直接冲销。
- 已日结记录在页面显示冻结状态，隐藏冲销按钮；后台再次校验，防止过期页面绕过。
- v11增量增加退款请求、不可删除的退款/冲销事件及退款边界；不推测回填历史退款。
- 当前及历史版本的净退款进入图片/PDF/CSV摘要。历史金额取当时快照，不被后续操作覆盖。
- 加密备份纳入请求、事件和顺序边界，逐项验证金额、客户、版本、冲销引用与日结净额。
  兼容v2–v10旧快照；恢复后关闭重开核账，不覆盖原库。
