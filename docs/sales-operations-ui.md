# 销售操作页优化（第二批）

本批候选版本0.1.6+7，数据库仍v9，不增加财务或库存规则。保留三步新开单；已确认单编辑仍是单页，本批只优化其日期选择、影响核对及更新图片提示，不宣称改单已改成三步。

## 变化

- 补收款独立页面：客户、单号、当前未收；金额留空，填写本次实际收到的钱，选择渠道后先核对再确认。校验正数、两位小数及当前未收上限，提交前重新读取单据；并发变化要求重新核对。
- 收款失败保留输入；已成功入账但刷新失败只允许重试刷新，不再次写收款。返回保护未提交输入，处理过程中禁止退出和重复提交，返回详情重新读取最新金额。
- 改单日期提供日历按钮并保留手输校验；差额、余额释放、待退款、退货影响确认可滚动。返回详情提示保存当前版本图片。
- 转余额确认增加来源单号并适配长内容滚动，保留所属客户及整笔来源和原事务保护；未增加现金退款或部分转入。
- 出库/退货逐行显示原数量、已处理、可处理；非法数量就地提示并定位首错。提交前逐行核对，本次确认才执行库存变动；取消核对保留输入、不提交。提交时锁定输入与返回，未提交离开需确认。

## 验证与限制

新增payment_page_test真实SQLite测试：超额校验、取消不入账、事务触发器注入失败后回滚并保留输入、重试后仅收20元。新增stock_operation_ui_test验证出库及退货超量拦截、确认取消、单次提交；库存SQL正确性另由既有集成套件覆盖。原履约UI测试增加“确认登记”操作，金额和数量断言未改。

全量结果与构建见release-evidence/sales-operations-{regression,analyze,build}-20261108.log。真机新版收款、改单、转余额、出库退货及大字/键盘专项本批NOT RUN。未操作手机上已保留的XS202611080001，也未清空数据。

无模式迁移或外部业务接口变更；新UI入口PaymentPage通过现有SalesStore操作。付款事务不新增幂等契约，页面内禁止并发及已成功后的重复写入；跨进程不确定入账结果仍须查询原单流水，不能据此宣称实现了跨进程付款幂等。
